# Phase 3 Implementation Guide

End-to-end order for regenerating the data and the results from scratch. Every step is a plain
`python` entry point run from the repo root; nothing is `exec()`'d into a notebook any more.
Historical notebooks are under `archive/notebooks/` and are not runnable.

## Precision requirement

Every step that touches the model must use the **unquantized bf16** model
(`shared.model_utils.load_model(quantize=False)`, the default). The committed detection, v3
ablation, mechanism-check and contradictory-context knows-fact numbers were produced under NF4
and are superseded. Model-dependent scripts refuse an NF4 model unless `--allow-nf4` is passed,
and every output records `precision`. Needs ~17 GB VRAM; run on RunPod/Vast, not Kaggle's free tier.

## Step 0 -- environment

`pip install -r requirements.txt`, HF token exported (`HF_TOKEN`) with access to
`meta-llama/Llama-3.1-8B-Instruct`. See `SETUP.md`.

## Step 1 -- build the data (three independent entry points)

All three write `data/<category>/prompts.jsonl` (uncertain set) and `controls.jsonl` (matched
low-uncertainty twins, `is_control: true`), 120 records each, 84 working / 36 held-out, seed 42.
Dataset revisions are pinned inside each script.

**Ambiguity** (tokenizer only, no GPU):
```bash
python person_A_ambiguity/preprocess_ambiguity.py --overwrite
```
Writes `data/ambiguity/review_log.jsonl` and `control_review_log.jsonl` (one accept/reject line per
raw AmbigQA record). Without `--overwrite`, an existing log is kept and a timestamped copy written.
`--pilot` prints singleAnswer annotation samples only.

**Lack of knowledge** (step a needs the GPU; step b tokenizer only):
```bash
python person_B_lack_of_knowledge/screen_templates.py            # -> template_screen_results.json
python person_B_lack_of_knowledge/rebuild_lack_of_knowledge_whitelisted.py   # -> prompts/controls + template_quota_report.json
```
`rebuild` derives the template whitelist from `template_screen_results.json` (gap >= 0.15). The
hard-coded 9-template fallback (`--use-fallback-whitelist`) exists only for reproducing the
committed set. `nec_templates.py --fetch` clones UnknownBench at the pinned commit.

**Contradictory context** (GPU, bf16):
```bash
python person_C_contradictory_context/preprocess_contradictory_context.py --verbose
```
Writes `knows_fact_log.jsonl` (every checked row: top-1 token, prob, pass/fail) and `provenance.json`
(precision, revisions, template overrides). Pilot with `--n 20 --verbose` and read the
`top1=... vs true=...` lines first.

**Induction check** (GPU): `python scripts/induction_check.py` measures uncertain-vs-control mean
top-1 for all three categories. Compare the two MEANS directly; do not rely on a per-item ceiling.
If a category shows no gap, fix the data before running anything downstream.

Commit `data/*/prompts.jsonl`, `data/*/controls.jsonl`, the review/knows-fact logs,
`template_screen_results.json`, `template_quota_report.json`, `provenance.json`.

## Step 2 -- detection (shared, on the NEW data)

```bash
python scripts/detect.py          # split-half validated activation-entropy correlation
```
Overwrites `candidate_neurons.json` and `full_correlation_distribution.json` -- intended. If the
stable set is smaller than before, do not pad it.

## Step 3 -- causal tests

```bash
python scripts/run_ablation.py      # mean-ablation, all categories + controls -> <--out-dir>/results_<category>.csv (+ ablation_means.json)
python scripts/frozen_norm.py       # frozen-norm control
python scripts/dose_response.py     # dose-response
python scripts/mechanism_check.py   # logit-lens mechanism check
```
Each script takes `--category` / `--candidates` / `--out` arguments; see `--help`.

## Step 4 -- statistics

```bash
python results/mixed_model_stats.py
python results/stats_significance.py
python results/merge_and_analyze.py
```
Regenerate and recommit `results/merged_summary.csv` and `results/cross_category_correlation.csv`.
